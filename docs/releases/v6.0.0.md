## LSADRA v6.0.0

v6.0.0 is the first release since v5.0.0 (2026-07-24). It moves online
detection off the ingest path, makes the live alert stream authenticated,
freezes the event schema, and rebuilds the supply chain so every install and
every release is reproducible and verifiable. It is a major version because
clients of the alert stream, the ingest API and the Python install all need
changes (see **Breaking changes**).

### Breaking changes

- **The live alert stream needs a login.** `/ws/alerts` now takes a JWT, either
  in the `bearer` WebSocket subprotocol or in an `Authorization` header, and
  closes unauthenticated connections before accepting them. Non-admin users
  see only their own alerts.
- **The dashboard's offline login is gone.** The React dashboard no longer
  falls back to a canned session when the API is unreachable, and it never
  shows demo data in a real session.
- **Ingest enforces event schema v1.** Events that do not match
  `docs/contracts/event-schema.v1.json` are rejected at the API boundary
  ([ADR 0006](../architecture/adr/0006-event-schema-v1-freeze.md)).
- **Dependencies install from hash-locked files.** `requirements.txt` now
  includes the locks under `requirements/`, which pin every package to one
  version and hash; pip checks the hashes. The optional PyTorch install comes from
  `requirements/torch.txt` (CPU build). See `requirements/README.md` for how
  to add or update a dependency.
- **JWT handling moved from python-jose to PyJWT.** python-jose is no longer
  installed; anything that imported `jose` from LSADRA's environment must
  switch.
- **The container runs as a non-root user** on a digest-pinned base image.
  Volumes mounted from the host must be writable by that user.

### Detection and ingestion

- Online detection runs in a background worker instead of inside the ingest
  request, so a slow model run no longer slows event intake.
- At 1,000 events/s the ingest p99 is now well under the 250 ms gate (82 to
  89 ms on the reference Windows machine, down from about 215 ms). Verified
  device credentials are cached briefly and re-verified in the background, and
  detection can no longer hold the interpreter long enough to stall requests
  (`LSADRA_THREAD_SWITCH_INTERVAL_MS`).
- The lateral-movement rule only looks at its 30-minute window, so its cost no
  longer grows with the size of the database.
- Narrative fields built from log data are sanitized before they reach the
  dashboard or a report.

### Operations

- The scheduler starts with the app (`LSADRA_SCHEDULER_ENABLED`) and keeps
  data for a bounded time (`LSADRA_RETENTION_DAYS`), deleting in batches that
  respect foreign keys.
- IP geolocation is opt-in (`LSADRA_GEO_RESOLUTION_ENABLED`): nothing leaves
  the host unless you turn it on.
- Dashboard KPIs and health work for non-admin users and show no made-up
  numbers.
- `/api/health` reports the running version, read from the one place the
  version is kept (`lsadra/__init__.py`).

### Supply chain and releases

- Every release runs the full CI suite on the tagged commit before anything
  is published. The container image ships with an SBOM and SLSA provenance, is
  signed with Sigstore (keyless), and carries a GitHub build attestation.
- Every GitHub Action is pinned to a full commit SHA. CodeQL, OpenSSF
  Scorecard, zizmor and dependency review run on the repository.
- Releases are cut by release-please from Conventional Commits, with a
  generated `CHANGELOG.md` and these hand-written notes.

### For contributors

- A labeled synthetic demo corpus and an API-replay seeder (`demo/`).
- An ingest benchmark harness with a committed baseline (`benchmarks/`).
- A contract test suite for every public storage function.
- Issue forms, starter labels, a contributor quick start that works on a fresh
  clone, documented DCO sign-off, and `CLAUDE.md` with the rules for AI coding
  agents.

### Upgrading from v5.0.0

1. Back up `data/` (the SQLite database and model files).
2. Reinstall dependencies from the locks in a fresh virtual environment:
   `pip install -r requirements.txt`, plus
   `pip install --no-deps -r requirements/torch.txt` if you use the
   autoencoder model.
3. Update any client of `/ws/alerts` to send a JWT.
4. Check that agents and scripts that post events send schema v1 events.
5. With Docker, pull the new image. Volumes written by the v5.0.0 image are
   owned by root; give them to uid 10001 (the image's user) before starting.
