## LSADRA v6.0.0

v6.0.0 is the first release since v5.0.0 (2026-07-24). Detection now runs
one tested rule set on the live path and stops alerting on every event; a
default install is closed to strangers; sessions, logins and model files are
hardened; and the supply chain is rebuilt so every install and every release
is reproducible and verifiable. It is a major version because operators,
clients of the alert stream and the ingest API, and the Python install all
need changes (see **Breaking changes** and **Upgrading**).

### Breaking changes

- **Secure by default.** Outside dev mode the server refuses to start without
  your own `LSADRA_JWT_SECRET` (32+ bytes, not a documented placeholder) and
  listens on `127.0.0.1` unless `LSADRA_API_HOST` says otherwise. On any other
  address it will not serve plain HTTP: it uses your certificate, a trusted
  proxy, or a self-signed certificate whose fingerprint agents can pin. Start
  it with `python -m lsadra.serve` so this policy applies.
- **No open sign-up.** Self-service sign-up is off outside dev mode
  (`LSADRA_ALLOW_SIGNUP`), and sign-ups that are allowed become analysts.
  Create the first admin with
  `python -m lsadra.admin_cli create-admin --username <name>`; admins add
  other accounts from the dashboard.
- **Stricter accounts and sessions.** Passwords need 12+ characters and may
  not be common passwords; repeated failed logins are rate limited; logging
  out, a password or role change, or disabling an account ends earlier
  sessions. Existing users sign in again after the upgrade.
- **Device keys are checked everywhere.** Heartbeats and device config need
  the device's key, and devices can be revoked or given a new key.
- **The live alert stream needs a login.** `/ws/alerts` now takes a JWT, either
  in the `bearer` WebSocket subprotocol or in an `Authorization` header, and
  closes unauthenticated connections before accepting them. Non-admin users
  see only their own alerts.
- **The dashboard's offline login is gone.** The React dashboard no longer
  falls back to a canned session when the API is unreachable, and it never
  shows demo data in a real session.
- **Ingest enforces event schema v1.** Events that do not match
  `docs/contracts/event-schema.v1.json` are rejected at the API boundary
  ([ADR 0006](../architecture/adr/0006-event-schema-v1-freeze.md)).
- **Dependencies install from hash-locked files.** `requirements.txt` now
  includes the locks under `requirements/`, which pin every package to one
  version and hash; pip checks the hashes. The optional PyTorch install comes from
  `requirements/torch.txt` (CPU build). See `requirements/README.md` for how
  to add or update a dependency.
- **JWT handling moved from python-jose to PyJWT.** python-jose is no longer
  installed; anything that imported `jose` from LSADRA's environment must
  switch.
- **The container runs as a non-root user** on a digest-pinned base image.
  Volumes mounted from the host must be writable by that user.

### Detection and ingestion

- One rule registry runs on the live path: 18 rules (brute force,
  credential stuffing, port scans, large transfers, LOLBin abuse, encoded
  PowerShell, persistence and more) plus the scheduled lateral-movement scan,
  each with an ID, version, ATT&CK v20 technique, tests and a committed
  scorecard. Anomalies no rule explains are no longer labelled T1190, and a
  normal event no longer raises an alert after baselining.
- A detection bench measures the true-positive rate per ATT&CK technique at
  fixed false-positive rates, with a committed baseline
  ([ADR 0007](../architecture/adr/0007-detection-stack.md) sets the detection
  stack this release starts on).
- Malformed timestamps or fields in incoming events can no longer stall
  online detection.
- Online detection runs in a background worker instead of inside the ingest
  request, so a slow model run no longer slows event intake.
- At 1,000 events/s the ingest p99 is now well under the 250 ms gate (82 to
  89 ms on the reference Windows machine, down from about 215 ms). Verified
  device credentials are cached briefly and re-verified in the background, and
  detection can no longer hold the interpreter long enough to stall requests
  (`LSADRA_THREAD_SWITCH_INTERVAL_MS`).
- The lateral-movement rule only looks at its 30-minute window, so its cost no
  longer grows with the size of the database.
- Narrative fields built from log data are sanitized before they reach the
  dashboard or a report.

### Security and data handling

- A hash-chained audit trail records logins, lockouts, account and role
  changes, device revokes and key rotations, backups and restores.
- Incidents are checked against the requesting user, not only their role.
- Agent install commands are verified by hash.
- Model files load only after their hashes match a signed manifest; training
  is gated behind a canary and every run leaves a model card.
- Guardrails for the optional LLM tier (local by default, proposal-only
  actions, a prompt-injection red-team corpus) are in place before that tier
  ships.

### Operations

- `docker compose up` serves the React dashboard as well as the API, both on
  the host's loopback only; the legacy Streamlit dashboard is behind the
  `legacy` profile.
- A dev container sets up Python, Node and dev mode in one step.
- The scheduler starts with the app (`LSADRA_SCHEDULER_ENABLED`) and keeps
  data for a bounded time (`LSADRA_RETENTION_DAYS`), deleting in batches that
  respect foreign keys.
- IP geolocation is opt-in (`LSADRA_GEO_RESOLUTION_ENABLED`): nothing leaves
  the host unless you turn it on.
- Dashboard KPIs and health work for non-admin users and show no made-up
  numbers.
- `/api/health` reports the running version, read from the one place the
  version is kept (`lsadra/__init__.py`).

### Supply chain and releases

- Every release runs the full CI suite on the tagged commit before anything
  is published. The container image ships with an SBOM and SLSA provenance, is
  signed with Sigstore (keyless), and carries a GitHub build attestation.
- Every GitHub Action is pinned to a full commit SHA. CodeQL, OpenSSF
  Scorecard, zizmor, dependency review, pip-audit and npm audit run on the
  repository, and CI also tests Python 3.13 and 3.14.
- Releases are cut by release-please from Conventional Commits, with a
  generated `CHANGELOG.md` and these hand-written notes.

### For contributors

- A labeled synthetic demo corpus and an API-replay seeder (`demo/`).
- An ingest benchmark harness with a committed baseline (`benchmarks/`).
- A contract test suite for every public storage function.
- Issue forms, starter labels, a contributor quick start that works on a fresh
  clone, documented DCO sign-off, commitlint on every PR commit, and
  `CLAUDE.md` with the rules for AI coding agents.
- The README no longer claims per-feature SHAP explanations on live alerts;
  that is planned for the supervised model.

### Upgrading from v5.0.0

1. Back up `data/` (the SQLite database and model files). Database
   migrations run on first start.
2. Reinstall dependencies from the locks in a fresh virtual environment:
   `pip install -r requirements.txt`, plus
   `pip install --no-deps -r requirements/torch.txt` if you use the
   autoencoder model.
3. Set `LSADRA_JWT_SECRET` to your own random value of at least 32 bytes:
   `python -c "import secrets; print(secrets.token_urlsafe(48))"`. Model
   files are re-verified against it and retrain if they do not verify.
4. Create an admin if you have none
   (`python -m lsadra.admin_cli create-admin --username <name>`), then start
   the server with `python -m lsadra.serve`.
5. Update any client of `/ws/alerts` to send a JWT, and make sure agents and
   scripts that post events send schema v1 events.
6. With Docker, pull the new image. Volumes written by the v5.0.0 image are
   owned by root; give them to uid 10001 (the image's user) before starting.
